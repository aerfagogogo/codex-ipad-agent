# Remote Ops：快速历史与任务岛精华

## 产品边界

这是基于 MimiRemote 的掌上 AI 运维台。第一版只强化四件事：浏览会话、处理审批、补充输入、快速恢复历史。它不复制桌面 IDE，也不新增一套指标仪表盘。

从旧 MimiTag 保留的只有任务岛状态模型：Codex 与 Claude 会话统一去重，审批、待输入、失败优先，点击仍进入真实会话。它作为原会话列表顶部的“需要处理”分组存在，不重复展示任务。

完整的旧仓库吸收取舍见 [`legacy-mimitag-extraction.md`](legacy-mimitag-extraction.md)。独立 Team 工作区、角色卡和 Claude 专用侧栏不会迁入；有价值的机制只通过统一 session 边界实现。

## FastNote 启发的同步方式

借鉴的是 local-first 机制，不直接同步 Codex/Claude 的原始数据库或会话文件：

1. 远端分页接口与实时事件仍是唯一权威源。
2. 每次成功取得首屏历史后，在当前连接 Profile 下写入设备端受保护快照。
3. 再次打开会话时先从磁盘恢复首屏，让内容立即可读；随后自动向远端对账并替换。
4. 切换或删除连接 Profile 时严格隔离或清除对应快照。

快照使用原子写入和系统文件保护，排除 iCloud 备份；单文件最多 8 MiB，每个 Profile 最多 64 个，最长保留 30 天。文件名使用 Profile 与会话 ID 的 SHA-256 摘要，缓存失败不会阻断原网络路径。

## 验收重点

- 已访问会话在网络往返前即可显示缓存首屏。
- 缓存命中后仍发起权威刷新，不把缓存变成第二个真相源。
- 不同远端 Profile 的相同会话 ID 不串数据。
- 审批、待输入、失败会话只在“需要处理”出现一次。
- 原有分页、economy/full 模式、WebSocket 实时尾流和控制能力保持不变。

## 后续增量

当前版本解决“访问过的长会话重新打开仍慢”。若要让从未打开过的会话也冷启动秒开，下一步应由 agentd 提供带游标的历史物化清单/增量包，App 在空闲与前台恢复时限量预热；不要用通用文件同步复制运行时数据库。
